# Запуск площадки на сервере — пошаговая инструкция

Время: около часа. Команды копируйте целиком и вставляйте в окно терминала (правой кнопкой мыши или Ctrl+Shift+V).

## Что понадобится (и сколько стоит)

| Что | Где | Примерно |
|---|---|---|
| Сервер (VPS) в РФ | Timeweb Cloud или Selectel | 800–1500 ₽/мес |
| Домен или поддомен | REG.RU / RU-CENTER, либо поддомен вашего сайта | 0–900 ₽/год |
| Почтовый ящик для писем | Яндекс 360 для бизнеса (или ваш почтовый сервис) | от 0 ₽ |
| Ключ DaData | dadata.ru | бесплатно (до 10 000 запросов в день) |
| Хранилище для копий бэкапов (рекомендуется) | Selectel или Yandex Object Storage | ~100 ₽/мес |

---

## Шаг 1. Сервер

1. Зарегистрируйтесь в **Timeweb Cloud** (timeweb.cloud) или **Selectel** (selectel.ru). Можно на юрлицо — оплата по счёту.
2. Создайте сервер:
   - операционная система: **Ubuntu 24.04**;
   - конфигурация: **2 ядра, 4 ГБ памяти, диск 50 ГБ**;
   - регион: Москва или Санкт-Петербург.
3. После создания в карточке сервера будут **IP-адрес** (вида `185.12.34.56`) и **пароль root**. Сохраните их.

## Шаг 2. Домен

1. Решите, по какому адресу будет площадка, например `tender.вашакомпания.ru`.
2. В личном кабинете того, где обслуживается домен (REG.RU, RU-CENTER или хостинг основного сайта), откройте **«DNS-записи»** / **«Управление зоной»** и добавьте запись:
   - тип **A**, имя **tender**, значение — **IP-адрес сервера** из шага 1.
3. Запись начинает работать за 15 минут — несколько часов. Пока ждёте — шаги 3–6.

## Шаг 3. Почта для писем

Пример для **Яндекс 360 для бизнеса**:
1. Создайте ящик, например `noreply@вашакомпания.ru`.
2. Войдите в этот ящик → **Яндекс ID → Безопасность → Пароли приложений** → создайте пароль для «Почты». Сохраните его.
3. Понадобятся: сервер `smtp.yandex.ru`, порт `465`, логин — полный адрес ящика, пароль — пароль приложения.

## Шаг 4. Ключ DaData

Зарегистрируйтесь на **dadata.ru** → Личный кабинет → **API-ключ**. Скопируйте его. Без ключа сайт не запустится: иначе реквизиты по ИНН были бы тестовыми.

## Шаг 5 (рекомендуется). Хранилище для копий бэкапов

Бэкапы делаются каждую ночь на самом сервере. Чтобы они уцелели, даже если сервер сломается целиком, — копия в облако:
- **Selectel**: Облачное хранилище (S3) → создать **контейнер** (бакет) → сервисный пользователь → **S3-ключи** (Access key и Secret key). Адрес: `https://s3.ru-1.storage.selcloud.ru`, регион `ru-1`.
- **Yandex Object Storage**: создать **бакет** → сервисный аккаунт → **статический ключ доступа**. Адрес: `https://storage.yandexcloud.net`, регион `ru-central1`.

## Шаг 6. Подключиться к серверу

- **Windows**: Пуск → наберите **PowerShell** → откройте.
- **Mac**: программа **Терминал**.

Введите (вместо `185.12.34.56` — ваш IP):
```
ssh root@185.12.34.56
```
На вопрос `Are you sure...` напишите `yes`, затем вставьте пароль root (символы при вводе не видны — это нормально) и нажмите Enter.

## Шаг 7. Установить Docker и защиту

Вставьте целиком и нажмите Enter:
```
apt update && apt install -y docker.io docker-compose-v2 git ufw && \
mkdir -p /etc/docker && echo '{"registry-mirrors": ["https://mirror.gcr.io", "https://dockerhub.timeweb.cloud"]}' > /etc/docker/daemon.json && \
systemctl restart docker && \
ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw --force enable
```
Это установит Docker (с зеркалами — на случай блокировки Docker Hub) и закроет на сервере всё, кроме входа по SSH и сайта.

## Шаг 8. Скачать проект и заполнить настройки

```
git clone https://github.com/Bubaster99/tendersistem.git /opt/tender && cd /opt/tender
cp .env.production.example .env
echo "POSTGRES_PASSWORD=$(openssl rand -hex 24)" >> .env
echo "AUTH_SECRET=$(openssl rand -hex 32)" >> .env
nano .env
```
Откроется редактор. Заполните:
- `DOMAIN` — адрес из шага 2 (без https), `APP_URL` — тот же адрес с `https://`;
- `SUPPORT_EMAIL`, `ADMIN_EMAIL`;
- `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` — из шага 3;
- `DADATA_API_KEY` — из шага 4;
- `BACKUP_S3_*` — из шага 5 (если делали).

Строки `POSTGRES_PASSWORD` и `AUTH_SECRET` в конце файла не трогайте — это случайные пароли, их создала команда выше.
Сохранить: **Ctrl+O**, Enter. Выйти: **Ctrl+X**.

## Шаг 9. Запустить

Убедитесь, что домен уже указывает на сервер (шаг 2), и выполните:
```
cd /opt/tender && docker compose -f docker-compose.prod.yml up -d --build
```
Первый запуск — 5–10 минут. Проверить, что всё поднялось:
```
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs app --tail 30
```
В журнале должно быть `Ready` и `Расписание запущено`. Если сайт не стартовал — в журнале будет написано, какую строку `.env` исправить.

Откройте в браузере `https://tender.вашакомпания.ru` — должен быть замочек и страница входа.

## Шаг 10. Первая настройка в админке

1. `https://ваш-адрес/admin/login` → ваш email → код придёт **на почту**.
2. **Объекты** → добавьте «Сахаров Парк» и «Широта на Павловском» (обложки лежат в проекте в папке `prisma/seed-assets`).
3. **Контакты** → снабженцы для подрядчиков. **Виды работ** → назначьте ответственных.
4. **Сотрудники** → добавьте снабженцев.
5. Создайте первый тендер.

## Бэкапы

- Каждую ночь в **03:00 по Москве** — база и все файлы в папку `/opt/tender/backups/ДАТА_ВРЕМЯ/`, хранятся 14 дней (`BACKUP_KEEP_DAYS`). Если заполнены `BACKUP_S3_*` — копия в облако.
- Журнал бэкапов: `cat /opt/tender/backups/backup.log`
- Сделать бэкап прямо сейчас:
  ```
  cd /opt/tender && docker compose -f docker-compose.prod.yml exec backup sh /backup.sh
  ```
- **Восстановить** (заменит текущую базу и файлы!):
  ```
  cd /opt/tender && ls backups
  sh deploy/restore.sh 2026-10-20_0300
  ```
  Скрипт спросит подтверждение — напишите `ДА`.

## Обновить сайт (когда выйдет новая версия)

```
cd /opt/tender && git pull && docker compose -f docker-compose.prod.yml up -d --build
```
Перед крупным обновлением сделайте бэкап вручную (команда выше).

## Если что-то не так

- Журнал сайта: `docker compose -f docker-compose.prod.yml logs app --tail 100`
- Перезапустить всё: `docker compose -f docker-compose.prod.yml restart`
- Не приходят письма — проверьте `SMTP_*` в `.env`, затем `docker compose -f docker-compose.prod.yml up -d` (подхватит изменения).
- Нет замочка / сайт не открывается — проверьте DNS-запись из шага 2: `ping tender.вашакомпания.ru` должен показывать IP сервера.

## Проверка на 2–3 знакомых подрядчиках

Попросите их с телефона:
1. Зарегистрироваться по ИНН (реквизиты должны подтянуться настоящие).
2. Заполнить анкету, настроить подписку.
3. Скачать документацию тестового тендера, подать КП, заменить его.
4. Рассказать, что было непонятно.

Вы со своей стороны: дождаться окончания приёма, посмотреть сравнение, выбрать победителя — участники должны получить письма с итогами.
